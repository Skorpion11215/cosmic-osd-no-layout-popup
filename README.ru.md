# COSMIC OSD — отключение всплывающего названия раскладки

[English documentation](README.md)

Минимальный неофициальный патч, который убирает **только всплывающую надпись языка** при переключении раскладки в COSMIC. Код индикаторов громкости, микрофона, яркости, системных диалогов и агента polkit не изменяется. Сочетания клавиш и настройки раскладок этот проект **не меняет**.

Проект не связан с System76 и не является универсальным расширением для всех версий COSMIC.

## Совместимость

Проверено на **Pop!_OS 24.04 / COSMIC / Wayland, x86_64**:

- пакет `cosmic-osd`: `1.10.0~1791315686~24.04~9b14ee0`;
- исходники: `9b14ee017fb8fdb7d03d73da597cf17b89d890f7`;
- компилятор: Rust 1.95.0.

Установщик откажется работать с другой версией пакета. Успешная сборка на другой архитектуре или ОС сама по себе не доказывает совместимость. Готовые бинарники не публикуются.

## Что изменено

Обработчик `KeyboardLayout(Event::Group(...))` в `src/components/app.rs` по-прежнему сохраняет текущую группу, но возвращает `Task::none()` вместо создания языкового индикатора. Служба OSD и её подписки не отключаются. Старый код отрисовки оставлен ради минимального патча; отсюда ожидаемое предупреждение компилятора о неиспользуемом варианте `KeyboardLayout`.

## Подготовка и сборка

Сохраните работу. Не перезапускайте OSD во время ввода пароля в системном диалоге: он обслуживает и polkit.

Проверьте версию:

```sh
dpkg-query -W cosmic-osd
```

Нужны Python 3.11+, Git, инструменты C/C++ и Rust 1.95.0 через rustup. Установите rustup по официальной инструкции Rust, затем:

```sh
rustup toolchain install 1.95.0 --profile minimal
```

Типичные зависимости Debian/Ubuntu; проверьте список перед установкой:

```sh
sudo apt-get install build-essential pkg-config cmake clang libclang-dev \
  libinput-dev libudev-dev libxkbcommon-dev libwayland-dev libdbus-1-dev \
  libasound2-dev libfontconfig1-dev libfreetype6-dev libgbm-dev \
  libegl1-mesa-dev libgles2-mesa-dev libssl-dev libpam0g-dev
```

Скрипты проекта сами не используют sudo и не устанавливают системные пакеты. Сборка скачивает зависимости и исполняет их build-скрипты; предварительно изучите код. Потребуется несколько гигабайт диска. Одно задание сборки уменьшает нагрузку, но **не ограничивает жёстко потребление памяти**. На машине с дефицитом памяти используйте дополнительную изоляцию ресурсов.

Склонируйте этот репозиторий через **Code → Clone** на GitHub, перейдите в его каталог:

```sh
bash scripts/build.sh
```

Скрипт получает официальный upstream, выбирает точный commit, применяет патч и выполняет `cargo check --locked` и сборку development-профиля. Переводы встраиваются через `rust-embed/debug-embed`: бинарник не зависит от расположения каталога исходников. Это рабочая проверочная сборка, не оптимизированный release-пакет.

Результаты: `build/cosmic-osd`, `build/build-info.json`, исходники и кэш в `build/source/`. `Cargo.lock` не изменяется. Уже существующий каталог `build/` скрипт не перезаписывает. Нужен интернет; доступность инструментария и upstream-зависимостей в будущем не гарантируется.

## Установка

**Без sudo**, после проверки исходников:

```sh
python3 scripts/manage.py install
```

Установщик проверяет версию пакета, архитектуру и контрольную сумму. Бинарник размещается в `~/.local/bin/cosmic-osd`, сведения — в `~/.local/share/cosmic-osd-no-layout-popup/install.json`. Уже существующий пользовательский OSD не перезаписывается. Системный `/usr/bin/cosmic-osd` остаётся нетронутым и служит оригиналом для отката. Контрольная сумма обнаруживает случайные изменения, но не является цифровой подписью.

Установка ничего не перезапускает. Для применения выйдите из сеанса и войдите снова либо перезапустите только OSD:

```sh
python3 scripts/manage.py restart
python3 scripts/manage.py status
```

Команда restart требует ровно один процесс OSD вашего пользователя с родителем `cosmic-session`. Проверяет порядок PATH сеанса, затем посылает SIGTERM только выбранному процессу через pidfd. Менеджер сеанса должен автоматически запустить его снова; перезапуск всего рабочего стола не запрашивается.

Если `~/.local/bin` не стоит перед `/usr/bin` в PATH сеанса, restart откажется работать. Сам по себе новый вход не исправляет неправильный PATH: сначала настройте окружение входа. Скрипты не редактируют shell startup-файлы.

## Проверка

В `status` путь запущенного процесса должен быть `~/.local/bin/cosmic-osd`. При смене языка всплывающая надпись должна исчезнуть. Остальные индикаторы и системные диалоги проверяются обычным использованием; ввод паролей и взаимодействие с диалогами проект не автоматизирует.

На закреплённой версии выполнены проверка типов, полная development-сборка, запуск `--help` на основной системе, проверка применимости патча и старт процесса с отвечающими D-Bus-интерфейсами. Это **не полный графический регрессионный тест**, включая polkit. В upstream-бинарнике нет unit-тестов. Тесты установщика этого проекта работают во временной домашней папке:

```sh
python3 -m unittest discover -s tests -v
bash -n scripts/build.sh
```

## Удаление и откат

```sh
python3 scripts/manage.py uninstall
```

Затем **выйдите из сеанса и войдите снова**. Удаление не завершает процессы, не трогает системный оригинал и отказывается удалять изменённый пользовательский бинарник. Если оригинал недоступен, удаление также отменяется.

Ручной откат, в том числе при утрате репозитория: переместите `~/.local/bin/cosmic-osd` за пределы PATH, убедитесь, что `/usr/bin/cosmic-osd` существует, и войдите в сеанс заново. Не удаляйте системный оригинал. Перед повторной установкой проверьте и удалите оставшуюся запись `~/.local/share/cosmic-osd-no-layout-popup/install.json`, только убедившись, что старый override действительно убран.

## Обновления COSMIC

**Пользовательский бинарник перекрывает будущие системные обновления OSD.** Перед обновлением COSMIC удалите override. Не оставляйте устаревшую версию надолго: OSD отвечает в том числе за диалоги аутентификации. После обновления используйте системный OSD, пока патч не будет проверен и пересобран для новой версии. Уже установленный override не отключается автоматически при обновлении пакетов.

Установщик намеренно отказывает при наличии любого пользовательского OSD, включая ранее установленный вручную вариант этого патча. Не перезаписывайте его принудительно: сначала сохраните файл и проверьте его происхождение.
